# 塩田川 その4 左岸 完成形ビューア

二級河川塩田川 河川改修工事（その4）左岸 完成形の 3D ビューアです。
スマホのブラウザで開いて、部品の切り替え・透過・測点での断面・計測ができます。
Android では現地で 1:1 の AR 表示もできます。

## 中身

```
  index.html              画面と UI
  app.js                  three.js のビューア本体
  sd_model.json           形状と線形と測点（scripts\sd_viewer.py が作る・約 650 KB）
  model.usdz              iPhone/iPad の AR Quick Look 用（実寸 1:1・全体版）
  model_ground.usdz       ★地面基準版（datum 8.200 m・合わせ箱つき・S32）
  AR基準点.csv / .sim     ★現地に設置する基準点6点（TS で出す用・cp932）
  manifest.webmanifest    ホーム画面に追加するための設定
  sw.js                   オフライン用（一度開けば電波が無くても見られる）
  icon-192.png / icon-512.png
```

`sd_model.json` は `scripts\sd_viewer.py` を実行すると作り直されます。
中身は AR モデル（`出力\AR\塩田川_AR_data.json`）＋設計線形＋測点対照表です。

## できること

```
  部品の表示ON/OFF   完成形の面・張ブロック・階段工・かごマット（平面図案／横断図案）など
  透過               面を透かして 基礎・均し・根固め を見る
  測点でスライス     現況測点で切って断面を見る。厚みも変えられる
  測点ラベル         成果簿の杭の位置と名前
  計測               2点をタップ → 水平距離・比高・斜距離
  タップで情報       どこを触っても 測点・離れ・標高・実座標が出る
  現地AR             1:1 で現地に重ねる（Android Chrome）
```

★かごマットは **平面図案（オリーブ）と横断図案（オレンジ）の2つ**が入っています。
どちらが正かは未確定です（引き継ぎ書 §8-c）。現地で見比べて監督員と決めてください。

## GitHub Pages で公開する手順

1. GitHub で新しいリポジトリを作る（例：`shiotagawa-viewer`）。**Public** にする
2. このフォルダの中身（`index.html` など7ファイル）をリポジトリ直下にアップロードする
   - ブラウザで「Add file」→「Upload files」にドラッグ＆ドロップでよい
3. リポジトリの **Settings → Pages** を開く
4. Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして Save
5. 1〜2分待つと `https://<ユーザー名>.github.io/shiotagawa-viewer/` で開ける

★AR とカメラは HTTPS でないと動きません。GitHub Pages は HTTPS なので大丈夫です。

## ★現地合わせ（基準点2点方式）── 精度が要るときはこちら

Quick Look は数値入力ができず位置合わせが目分量になるので、**現地に基準点を6点
設置して、そこに合わせる方式**を用意しました。ビューアの「現地合わせ」ボタンです。

### 準備（一度だけ）

```
  1) AR基準点.sim を TS に入れて、6点を現地に出す（鋲・杭）
     天端頂点（設計中心線から離れ 10.600）の上、39 m 間隔
     点名  設計追距    X(北)       Y(東)      計画天端高
     AR1   1914.000  84708.883  78794.384   8.427
     AR2   1953.000  84711.636  78756.179   8.557
     AR3   1992.000  84716.817  78718.054   8.687
     AR4   2031.000  84722.781  78679.513   8.817
     AR5   2070.000  84728.744  78640.972   8.947
     AR6   2109.000  84737.282  78605.926   9.078
  2) ★打った杭の頭の標高を実測する
  3) ビューアの「現地合わせ」→「基準点の標高」に実測値を入れて保存
     （端末に保存されます。計画天端高のままだと上下にずれます）
```

### ★2つのモードは別物（混同しやすい）

```
  「現地合わせ」  自前のカメラ重ね。★平面検出は無い（使っていない）。
                  基準点に立って 方位を解く。高さは基準点の標高で決まる＝★絶対値
  「AR（実寸）」  iOS 標準の AR Quick Look。★平面検出がある（床を探す）。
                  ★高さは「検出した床」基準。モデルの最下端が床に乗る＝★相対値
  → 「iPhoneを動かして開始」の案内が出るのは AR（実寸）だけ。現地合わせには出ない
```

### 現地での手順

```
  1) 基準点のどれかに立つ
  2) 「現地合わせ」を押す（カメラと「動作と方向」の許可を出す）
  3) 「立っている点」を選ぶ／★「カメラの高さ」を入れる
     ＝ 杭の頭から ★カメラのレンズまで の高さ。目の高さではない。
       三脚なら 雲台＋端末の取付位置まで含めて実測する（±1 cm でよい）
  4) 「狙う点」で別の基準点を選び、★画面中央の十字にその杭を重ねて「記録」
  5) これで完成形がカメラ映像に重なる。見回すと追従する
  6) さらに別の基準点で「記録」すると、前の点とのずれ量が出る（合わせの検算）
```

### 精度

立っている点は測量で出した既知点なので**カメラ位置は正確**、上下と傾きは重力
センサ（正確）、**方位だけが未知**です。十字に重ねて記録すると、その向きが
ちょうどその点を向くように姿勢を補正するので、画角に関係なく決まります。

```
  計算上の検算（センサのピッチ誤差 0.5° を与えた場合の残差）
    AR1 に立ち AR2 で合わせ → AR3 0.06 m ／ AR4 0.14 m ／ AR6 0.35 m
    AR6 に立ち AR1 で合わせ → 他点は 0.02 m 以内
  方位の誤差が横ずれに効く量
    0.2° ずれ →  39 m 先 0.14 m ／ 100 m 先 0.35 m ／ 195 m 先 0.68 m
    0.5° ずれ →  39 m 先 0.34 m ／ 100 m 先 0.87 m ／ 195 m 先 1.70 m
```

```
  ★歩くとずれます（カメラ位置を立っている点に固定しているため）。
    移動したら、その点を選び直して合わせ直してください。
  ★画角は端末ごとに違います。基準点6点はほぼ一直線（開き角 2〜5°）なので
    計算では決まりません。初回だけ「画角」スライダーで、
    手前の法肩線などが実物と合うところに調整してください（端末に保存されます）。
  ★出来形の判定には使えません。形・納まり・干渉の確認までです。
```

### ★S29 で入れたもの（精度を上げる3点＋印刷）

```
  1) ★ルーペ  十字のまわりを 2/3/5/8 倍で拡大表示する。
     指し誤差が 0.03° → 0.01° 級まで下がる。★一番効く
     「現地合わせ」パネルの下にチェックと倍率がある

  2) ★複数点の平均  記録を1点で上書きせず、記録した全点の
     方位・仰角を平均して姿勢を作る（最小二乗）。
     ★1点だけ 0.2° 指し損ねても、5点の平均なら方位の誤りは 0.04° に薄まる（検算済み）
     ・同じ点をもう一度記録すると 上書きになる
     ・2点目以降は「最大残差 ○○°（○○ m 先で ○○ m）」が出る。合わせの検算になる
     ・「狙う点」は 記録するたびに ★まだ記録していない中で一番遠い点 に自動で進む

  3) ★タップした点でも記録できる  画面のどこかをタップすると その向きで記録する
     （十字に重ねなくてよい）。ただし指の精度は ±0.3° 程度なので、
     ★精度が要るときは 十字＋ルーペ

  4) ★印刷（PC 向け）  「表示」パネルの一番下「この画面を印刷」。
     いま見えている画面を A4 横で印刷（PDF 保存も可）。
     工事名・範囲・断面位置・表示中の部品・座標系・日時の表が付く。
     現地合わせ中に押すと カメラ映像も一緒に写る
```

### ★記録の進め方（S31：チップで見える）

```
  1) 「狙う点」は 最初から ★一番遠い点（AR6 など）が入っている。
     そのまま その杭を十字に重ねて「十字に重ねて記録」を押す
  2) 記録すると チップの AR6 が ★緑＋✓ になる。
     「狙う点」は ★自動で 次に遠い未記録の点 に進む（AR5 → AR4 …）
     ★元に戻っているように見えるのは、その点をまだ記録していないから
  3) 2〜3点も記録すれば十分。「○点の平均で合わせ済」と
     「最大残差 ○○°（○○ m 先で ○○ m）」が出る
  4) 手で選び直したいときは ★チップを押す。同じ点をもう一度記録すると上書き

  チップの色  緑＋✓＝記録済 ／ 赤枠＝いま狙っている点 ／ 灰色（立）＝立っている点
```

### ★狙う点は「一番遠い点」を選ぶ

```
  実測（下の精度の節）
    AR1 に立ち ★AR2（38 m）で合わせ → AR6 で 0.35 m ずれた
    AR6 に立ち ★AR1（191 m）で合わせ → 他点は 0.02 m 以内
  → 逆算すると 指し誤差 ≒ 0.03°／立ち位置の誤差 ≒ 0.07 m 相当。
    ★立ち位置の誤差が支配的。近い点で合わせると それが方位の誤りに化ける
      （p / D。D=38 m なら 0.07 m が 0.11°、D=191 m なら 0.02°）
  ★対策  ・狙う点は 見えている中で 一番遠い点にする
          ・三脚で 鋲の真上に据える。カメラの高さ（レンズまで）も実測する
```

### 歩いたときのずれ量（AR1 に立って合わせ、天端を上流へ歩いた場合）

視差だけのずれなので、**近くを見るほど大きく、遠くを見るほど小さい**。

```
  狙う所                     2m歩く   5m歩く  10m歩く  20m歩く
  足元の法尻・法肩（〜10 m）   2 m     5〜6 m  11〜13 m  24〜27 m   ★使えない
  20 m 先の法尻              0.9 m    2.2 m    4.5 m   10.5 m
  20 m 先の法肩              0.2 m    0.6 m    1.2 m    3.4 m
  50 m 先の法尻              0.4 m    0.9 m    1.8 m    3.6 m
  50 m 先の法肩              0.1 m    0.2 m    0.4 m    0.7 m
  100 m 先の法肩             0.1 m    0.2 m    0.3 m    0.6 m
  上流端（190 m 先）         0.2 m    0.4 m    0.9 m    1.7 m
```

```
  目安  ずれ ≒ 歩いた距離 × sin(歩いた向きと 見ている向きの角度)
        → 進行方向の遠景はあまり狂わない。真横・足元は歩いた分そのままずれる
  運用  ・足元の納まりを見るときは その基準点から動かない
        ・5 m 以上動いたら合わせ直す（基準点は 39 m 間隔）
        ・遠景の全体像だけなら 20 m 程度動いても 1 m 前後
        ・しゃがむ／立つでカメラの高さが変わったときも同じ。入れ直す
  ★歩き回って見たいときは iPhone の「AR（実寸）」（Quick Look）の方が向いている。
    ARKit が位置を追うので歩いても保つ。ただし初期配置は目分量になる
```

## ★モデルに入っている AR基準点のポール（S26）

モデルの中に **AR1〜AR6 のポール（赤）** が入っています。**ポールの先端（下端）が
基準点そのもの**です。AR1 だけ 3.0 m、他は 2.0 m にしてあるので下流端が分かります。

Quick Look も SketchUp Viewer も ARKit で歩いてもずれませんが、**置く位置は目分量**です。
このポールを現地の鋲に合わせれば、そこが埋まります。

```
  1) AR基準点.sim を TS に入れて AR1〜AR10 の鋲を出しておく（天端6点＋法尻4点）
  2) Quick Look（または SketchUp Viewer）でモデルを置く
  3) ★AR1 のポールの先端を AR1 の鋲に乗せる（ドラッグ）
  4) ★AR2 のポールが AR2 の鋲に重なるまで回す（2本指）
  5) あとは触らない。歩いても ARKit が位置を保つ
```

```
  精度の目安  鋲に ±0.1 m で乗せられれば 方位 ±0.15°
              → 195 m 先で ±0.5 m ／ 39 m 先で ±0.1 m
  ★39 m 離れた2点で合わせるので方位が効く。1点だけだと回転が決まらない
  ★「現地合わせ」（十字方式）の方が精度は上（他点 0.02〜0.35 m）だが歩けない。
    歩いて見る → ポール方式 ／ 一点から精度よく見る → 現地合わせ、で使い分ける
```

### 標高を実測値にする### 標高を実測値にする

```

    点名,標高
    AR1,8.431
    AR2,8.560

### ★地面基準版の USDZ ＋ 合わせ箱（S32）── Quick Look でも XYZ を決める

```

  model_ground.usdz   datum 8.200 m より下を切り落とした版（0.27 MB）

    ★立方体の一辺に合わせるより、細い腕の交点を鋲に重ねる方が精密

  4) ★小さい箱が AR2〜AR6 の鋲に乗るまで 2本指で回す
  5) 触らない。歩いても ARKit が保つ
```

```
  ★高さの誤差 ＝ 置いた地面の標高 − 8.200

## ★なぜ Quick Look と SketchUp で差があるのか（S36）

```
  同じ ARKit を使っている。差は「その上に載っているソフト」
  AR Quick Look    ★iOS の標準機能。USDZ を表示するだけで UI は Apple が固定。
                   レイヤ切替・配置基準の変更・数値入力は無い。
                   ★USDZ 自体にタグ／レイヤの概念が無い（COLLADA と同じ・§8-14）
                   配置は ★バウンディングボックスの底 を平面に乗せる固定仕様
  SketchUp Viewer  ★専用アプリ。.skp のタグ・シーン・断面がそのまま生きる。
                   AR の配置 UI も自前なので 基準の取り方を自由に作れる

  Android でも  Scene Viewer（glTF）は同じく固定 UI ＝ 差は埋まらない
  ★埋まるのは 自作 web の方。Android の Chrome は WebXR に対応しているので、
    このビューアの中で AR ができる → 鋲基準の配置・部品の切替・高さ入力が全部使える
    （iOS の Safari は WebXR 非対応。同じことをするならネイティブアプリが要る）
```

## ★現地で標高を入れる（S43）

レベルで測った鋲の頭の標高は、**現地でアプリに直接入れられます**。CSV も 作り直し.bat も
GitHub 更新も要りません。

```
  設定パネル → 「★基準点の標高（現地で入れる）」
    ① AR1〜AR10 の欄に 実測標高（T.P. m）を入れる
    ② 「保存」
    → 現地合わせ（自作AR）に その場ですぐ効く。ポールと十字もその高さに動く
    ※ この端末のブラウザにだけ保存されます（localStorage）
```

```
  「書き出す」  いま入っている値を CSV にして 枠に出す＋クリップボードにコピー
                メール／AirDrop／メモ で PC に送る
  「貼り付けて読み込む」  枠に CSV を貼って押すと 読み込む
                （別の端末で入れた値を移すとき・PC で作った値を現地に持ち込むとき）
  「元値に戻す」  データに入っている値（＝USDZ と同じ値）に戻す
```

### AR（実寸／Quick Look）はどうなるか

USDZ は作り置きのファイルなので、**現地で入れた値ではその場では動きません。**
代わりに、同じパネルの下に「十字を鋲に重ねたあと 何 m 上げ下げするか」が出ます。

```
  例）AR7　モデルを 0.043 m 上げる
      → Quick Look で 十字を鋲に重ねたあと、2本指で上に 0.043 m ドラッグ
```

きちんと直すときは、書き出した CSV を PC の `出力\AR基準点_実測Z.csv` に貼って
`作り直し.bat` → GitHub 更新。これで USDZ も 全員のビューアも 実測値になります。
